<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input -> formula | Weight text field accepts free-form digits that are parsed and used in arithmetic |
| Calculator -> SettingsRepository | Computed recommendation (int) crosses from UI to data layer via updateTargetWithHistory() |
| SharedPreferences flag | Boolean flag gates first-launch flow; tampering could skip or loop onboarding |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | Weight TextFormField | mitigate | FilteringTextInputFormatter.digitsOnly blocks non-digit input at keyboard level; int.tryParse() + range validation (1-300) as defense in depth; clamp(1000, 4000) on formula output prevents unreasonable targets |
| T-11-02 | Information Disclosure | Calculator form state | mitigate | Sex/weight/climate stored only in widget-local setState -- never written to SharedPreferences, Drift, or any persistence layer; widget disposal clears all state; privacy disclaimer visible on screen |
| T-11-03 | Denial of Service | GoRouter redirect | mitigate | Redirect loop guards: `if (state.matchedLocation == '/calculator') return null;` and `if (state.matchedLocation == '/permission') return null;` prevent infinite redirect cycles |
| T-11-04 | Tampering | updateTargetWithHistory(int) | accept | The method already validates newTargetMl > 0 (throws ArgumentError); further range validation in the formula (clamp 1000-4000) ensures only reasonable values reach the repository; single-user local app with no remote attack surface |
| T-11-05 | Spoofing | drinky_calculatorShown SharedPreferences key | accept | Local-only storage on a single-user device; no meaningful attack vector for modifying this boolean flag; worst case is seeing the calculator again on next launch |
</threat_model>
