## Typography

Material 3 TextTheme roles already used in codebase. Phase 6 changes NO typography roles; the only text content change is the ring center string format.

Declared sizes: 4 (11px, 14px, 16px, 28px). Declared weights: 2 (400 regular, 600 semibold).

| Role | M3 Token | Size | Weight | Usage in Phase 6 |
|------|----------|------|--------|-------------------|
| Body | bodyLarge | 16px | 400 (regular) | Timeline entries, day summary text |
| Body secondary | bodyMedium | 14px | 400 (regular) | Empty state body, subtitle text, timeline timestamps, settings section headers |
| Heading | headlineMedium | 28px | 400 (regular) | Progress ring center text (L-display lives here), streak count, empty state heading |

Phase 6 ring text change: the `headlineMedium` role remains at 28px/400. Only the string content changes from `'$totalMl / $target ml'` to `'{currentL} / {goalL} L'`.

Elements previously at titleLarge (22px) now use headlineMedium (28px): streak count display, empty state heading.
Elements previously at weight 500 (medium) now use weight 400 (regular): timeline timestamps, settings section headers, settings card values.

## Color

### Visual Hierarchy

60% surface/background (`colorScheme.surface` as Scaffold background across all screens), 30% container variants and surface variants (`surfaceContainerLow`, `surfaceContainerHighest` for cards, ListTiles, ring track), 10% primary/semantic accent (ring fill, buttons, highlights, navigation active indicator).

### Theme Architecture (Phase 6 change)

Phase 6 replaces the static `colorSchemeSeed: Colors.blue` with a dynamic/fallback dual-theme system:

| Condition | Light ColorScheme Source | Dark ColorScheme Source |
|-----------|------------------------|----------------------|
| Android 12+ (API 31+) | `lightDynamic` from `DynamicColorBuilder` | `darkDynamic` from `DynamicColorBuilder` |
| Android < 12, all iOS | `ColorScheme.fromSeed(seedColor: Colors.blue)` | `ColorScheme.fromSeed(seedColor: Colors.blue, brightness: Brightness.dark)` |

**themeMode:** `ThemeMode.system` -- follows device setting, no manual toggle.

### Dynamic Color Roles (from ColorScheme)

Material 3 ColorScheme surfaces, inherited from the dynamic or seed palette. Not hardcoded.

| Role | Usage | Source |
|------|-------|--------|
| Dominant surface | `colorScheme.surface` | Background of all Scaffolds |
| Secondary surface | `colorScheme.surfaceContainerLow`, `surfaceContainerHighest` | Card fills, ListTile fills, ring track |
| Accent (primary) | `colorScheme.primary` | AppBar, progress ring (non-goal-met), FAB, active controls |
| Error | `colorScheme.error` / `errorContainer` | Permission-denied banner |

Accent reserved for: progress ring fill (when goal not met), navigation active indicator, slider thumb/track, AppBar text, FilledButton default.

### Semantic Colors (Phase 6 change -- brightness-adaptive)

These are hardcoded Material Colors used for goal-status communication. Phase 6 makes them brightness-aware.

| Semantic | Light Mode | Dark Mode | Elements |
|----------|-----------|-----------|----------|
| Goal met (green) | `Colors.green.shade600` | `Colors.green.shade400` | Progress ring fill when `isGoalMet`, ring center text color when `isGoalMet`, calendar day fill (met), calendar day text (met) |
| Goal missed (red) | `Colors.red.shade600` | `Colors.red.shade400` | Calendar day fill (missed + past), calendar day text (missed + past) |
| Streak (orange) | `Colors.orange.shade700` | `Colors.orange.shade400` | Streak fire icon on history screen |
| Partial (orange) | `Colors.orange.shade700` | `Colors.orange.shade400` | Calendar day fill (partial, if applicable) |

**Brightness detection pattern:**
```dart
Theme.of(context).brightness == Brightness.dark
    ? Colors.green.shade400
    : Colors.green.shade600
```

**Calendar day fill opacity:** `withValues(alpha: 0.15)` -- unchanged from v1.0.

## Copywriting Contract

Phase 6 changes exactly ONE piece of user-facing text (the progress ring center). All other copy is unchanged.

| Element | Copy | Source |
|---------|------|--------|
| Ring progress (normal) | `'{currentL} / {goalL} L'` e.g. `'1,75 / 2,00 L'` | NEW in Phase 6 (was `'$totalMl / $target ml'`) |
| Ring progress (goal met) | `'Goal reached!'` | UNCHANGED from v1.0 |

| Error state | `'Something went wrong loading your data. Restart the app if this persists.'` | UNCHANGED (recovery path added) |

### L-Display Formatting Rules

| Rule | Specification |
|------|---------------|
| Conversion | `amountMl / 1000` (int to double) |
| Decimal places | Exactly 2, always (e.g. `2,00` not `2`) |
| Decimal separator | Locale-aware via `intl.NumberFormat` (comma for IT/DE, period for US/UK) |
| Unit label | `' L'` appended once at the end, after the goal value |
| Format pattern | `'{current} / {goal} L'` |
| API | `NumberFormat.decimalPatternDigits(locale: Intl.getCurrentLocale(), decimalDigits: 2)` or equivalent producing exactly 2 decimal places |
| Scope | Home screen progress ring center ONLY |

### Destructive Actions

No new destructive actions in Phase 6. The existing UNDO SnackBar is a non-destructive undo affordance. No confirmation dialogs needed.
