## Verdict: PASS

All eight success criteria are fully satisfied. The data layer (Plan 01) correctly adds `watchTargetForDate` to `TargetHistoryDao`, the `applyFromTomorrow` BoolColumn to the `UserSettings` table with a v2 schema migration, and the `updateTargetWithHistory` dual-write method to `SettingsRepository`. The provider layer (Plan 02) delivers `TodayDateKey` as a keepAlive Notifier with a single-shot midnight `Timer` (no polling), `effectiveTargetForDateProvider` as a keepAlive stream family with a 2000 ml fallback, `allTargetHistoryProvider` returning `Stream<List<TargetHistoryEntry>>` using the plain domain entity, and an updated `streak` provider using `asyncExpand` over `targetHistoryDao.watchAll()` for per-day target evaluation. The UI layer (Plan 03) correctly wires all three screens: `HomeScreen` drops all legacy `_dateKey`/`Timer.periodic` code and reads both `todayDateKeyProvider` and `effectiveTargetForDateProvider`; `HistoryScreen` watches `allTargetHistoryProvider` and evaluates each calendar day via `_findActiveTarget`; and `SettingsScreen` routes slider changes through `updateTargetWithHistory` and exposes the `SwitchListTile` toggle for `applyFromTomorrow`. The generated file `stream_providers.g.dart` contains `todayDateKeyProvider`, `effectiveTargetForDateProvider`, and `allTargetHistoryProvider`, confirming code generation completed successfully.
