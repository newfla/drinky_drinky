## Spacing Scale

Declared values (must be multiples of 4). Inherited from v1.0 codebase and Phase 6, with one new usage note for the bottom sheet.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline padding, icon gaps, horizontal gap between preset buttons in sheet |
| sm | 8px | Compact element spacing, SizedBox between text lines, SnackBar margin |
| md | 16px | Default element spacing, horizontal page padding, sheet internal padding, card margins |
| lg | 24px | Section spacing within the sheet (presets section to custom input section) |
| xl | 32px | Layout gaps (previously buttons to timeline; now ring to timeline since buttons are removed) |
| 2xl | 48px | Top padding above progress ring |
| 3xl | 64px | Not currently used |

Exceptions: FAB touch target follows Material 3 default (56px diameter, 48px minimum touch target). This is a Material 3 framework default, not a custom override.

## Typography

Material 3 TextTheme roles. Phase 7 introduces one new text context (sheet heading) using an existing role.

Declared sizes: 4 (11px, 14px, 16px, 28px). Declared weights: 2 (400 regular, 600 semibold).

| Role | M3 Token | Size | Weight | Line Height | Usage in Phase 7 |
|------|----------|------|--------|-------------|-------------------|
| Body | bodyLarge | 16px | 400 (regular) | 1.5 | Timeline entries, preset button labels in sheet, custom ml TextField value |
| Body secondary | bodyMedium | 14px | 400 (regular) | 1.5 | Empty state body text (updated copy), TextField hint/helper text |
| Heading | headlineMedium | 28px | 400 (regular) | 1.2 | Progress ring center text (unchanged) |
| Label | labelSmall | 11px | 400 (regular) | 1.5 | Small captions, settings section headers |
| Sheet section label | titleMedium | 16px | 600 (semibold) | 1.2 | "Add Water" sheet title / drag handle label (if used) |

Note: `titleMedium` (16px/600) is already used in the settings screen for card values. No new font size introduced.

Note: The 2px gap between `bodyMedium` (14px) and `bodyLarge` (16px) is intentional -- these are standard Material 3 type scale tokens. They serve distinct semantic roles: `bodyLarge` is primary content text, `bodyMedium` is secondary/supporting text. The visual difference is subtle but consistent with M3 guidelines.

## Color

### Visual Hierarchy

Unchanged from Phase 6. 60/30/10 split:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` | Scaffold background, sheet background (inherits surface via `showModalBottomSheet`) |
| Secondary (30%) | `colorScheme.surfaceContainerLow`, `surfaceContainerHighest` | Cards, ListTiles, ring track, sheet surface variant |
| Accent (10%) | `colorScheme.primary` | Preset FilledButton fills, custom submit FilledButton fill, progress ring (non-goal-met) |
| Destructive | `colorScheme.error` / `errorContainer` | Not used in Phase 7 (no destructive actions) |

Accent reserved for: preset FilledButtons in sheet, custom submit FilledButton in sheet, progress ring fill (when goal not met).

Note: The FAB uses `colorScheme.primaryContainer` (not `primary`) per Material 3 defaults -- `primaryContainer` background with `onPrimaryContainer` icon. This is outside the accent 10% budget as it is a container-emphasis surface, not a high-emphasis accent.

### Theme Architecture

Inherited from Phase 6. Dynamic color on Android 12+, blue seed fallback otherwise. `ThemeMode.system`. No changes in this phase.

### Semantic Colors

Unchanged from Phase 6. Goal-met green (brightness-adaptive), goal-missed red, streak orange. No new semantic colors in Phase 7.

### FAB Color

The FAB uses Material 3 defaults: `colorScheme.primaryContainer` background with `colorScheme.onPrimaryContainer` icon. No custom color override.

### Sheet Surface

`showModalBottomSheet` inherits the active theme's surface color automatically. No explicit `backgroundColor` override. The sheet respects light/dark mode via the theme.

### FAB Behavior

| Property | Value | Notes |
|----------|-------|-------|

| Position | `FloatingActionButton` default (bottom-right) | Material 3 default placement |

| `onPressed` | Calls `showModalBottomSheet(...)` | Opens the intake sheet |
| Hero tag | Default (auto) | Only one FAB in the app |

### Sheet Open/Close

| Trigger | Action |
|---------|--------|
| FAB tap | `showModalBottomSheet` opens with standard bottom-up animation |
| Drag down on handle | Closes sheet (Material 3 default) |
| Tap outside sheet | Closes sheet (Material 3 default, `isDismissible: true`) |
| Preset button tap | Sheet closes (`Navigator.pop(context)`), then SnackBar shows (D-01) |
| Custom submit tap | Sheet closes (`Navigator.pop(context)`), then SnackBar shows (D-02) |
| Back button/gesture | Closes sheet (Material 3 default) |

### Preset Buttons in Sheet

| Property | Value |
|----------|-------|
| Widget | `FilledButton` |
| Layout | `Row` with 3 `Expanded` children, each containing a `FilledButton` |
| Label format | `'+{amountMl} ml'` (e.g., `'+150 ml'`, `'+250 ml'`, `'+500 ml'`) |
| Data source | `ref.watch(drinkPresetsProvider)` from HomeScreen, passed as parameter; `.take(3)` applied |
| onPressed | Calls callback that runs `Navigator.pop(context)` then `_onQuickAdd(preset.amountMl)` |

## State Contract

### Data Flow

```
HomeScreen (ConsumerStatefulWidget)
  |
  +-- ref.watch(drinkPresetsProvider) --> List<DrinkPresetEntity>
  |     |
  |     +-- .take(3) --> passed to sheet as parameter
  |
  +-- FAB.onPressed --> showModalBottomSheet(...)
  |     |
  |     +-- _IntakeBottomSheet(presets: presets.take(3), onAdd: _onQuickAdd)
  |           |
  |           +-- Preset tap: Navigator.pop() then onAdd(preset.amountMl)
  |           +-- Custom submit: Navigator.pop() then onAdd(parsedMl)
  |
  +-- _onQuickAdd(int amountMl) --> existing logic (DB insert, SnackBar, undo)
```

### Sheet Widget Contract

The sheet content widget receives:
- `List<DrinkPresetEntity> presets` (already `.take(3)` applied)
- `void Function(int amountMl) onAdd` callback

The sheet does NOT:
- Access providers directly (D-09: stateless with respect to DB writes)
- Call `ref.read` or `ref.watch`
- Manage its own TextEditingController lifecycle beyond standard StatefulWidget dispose

### Settings Presets Contract

`_presetsCard` in `settings_screen.dart` applies `.take(3)` to the presets list before mapping:
```dart
presets.take(3).map((preset) => ListTile(...))
```

No DAO changes. `DrinkPresetDao.watchAllPresets()` continues to return all rows. The `.take(3)` filter is at the presentation layer only (D-06).
