<objective>
Set up the complete Flutter localization pipeline and wire it into the app.

This plan creates l10n.yaml, adds flutter_localizations SDK dependency, configures
generate: true in pubspec.yaml, creates the context.l10n convenience extension,
wires MaterialApp.router with localizationsDelegates and supportedLocales (per D-03,
D-04, D-05), calls initializeDateFormatting() in main() (L10N-03), and adds the
locale parameter to TableCalendar (D-06).

After this plan, the gen-l10n pipeline is ready. Plan 02 creates the full app_en.arb
and runs gen-l10n to produce the generated files.

Purpose: Establish the l10n infrastructure so that once app_en.arb is authored (Plan 02),
the app resolves device locale and provides translated Material widgets.

Output: l10n.yaml, pubspec.yaml changes, lib/l10n/l10n_extensions.dart, modified main.dart
and history_screen.dart.
</objective>

<task type="auto">
  <name>Task 2: Wire MaterialApp.router, initializeDateFormatting, and TableCalendar locale</name>
  <files>lib/main.dart, lib/presentation/screens/history_screen.dart</files>
  <action>
  1. Edit lib/main.dart to add initializeDateFormatting() call (L10N-03, D-06):

     Add import: import 'package:intl/date_symbol_data_local.dart';
     Add import: import 'package:drinky_drinky/l10n/generated/app_localizations.dart';

     In the main() function, AFTER WidgetsFlutterBinding.ensureInitialized() and
     BEFORE the timezone init block, add:

     // L10N-03: Initialize date formatting for all locales.
     // table_calendar uses intl internally for month/day names.
     await initializeDateFormatting();

     Call with no arguments -- the no-arg form loads all locale data.

  2. Edit lib/main.dart DrinkyDrinkyApp.build() to add localizationsDelegates and
     supportedLocales to MaterialApp.router (per D-03, D-04, D-05):

     On the MaterialApp.router widget, add these two named parameters BEFORE
     the existing theme: parameter:

     localizationsDelegates: AppLocalizations.localizationsDelegates,
     supportedLocales: AppLocalizations.supportedLocales,

     AppLocalizations.localizationsDelegates is a generated convenience getter that
     includes all 4 delegates (AppLocalizations.delegate, GlobalMaterialLocalizations,
     GlobalWidgetsLocalizations, GlobalCupertinoLocalizations) per D-03.

     AppLocalizations.supportedLocales is generated from the ARB files with English
     first (per preferred-supported-locales: [en] in l10n.yaml) per D-04/D-05.

     Keep title: 'Drinky Drinky' as-is (brand name, not localized).
     Do NOT add localeResolutionCallback (per D-04 -- basicLocaleListResolution is
     automatic when supportedLocales is set).

  3. Edit lib/presentation/screens/history_screen.dart to wire TableCalendar locale (D-06):

     On the TableCalendar widget (currently at line 212), add the locale parameter
     as the first named parameter:

     locale: Localizations.localeOf(context).toString(),

     This passes a String like 'en' or 'it' to TableCalendar, which uses it
     internally with intl DateFormat for month and day name rendering.

  Note: These changes reference the generated AppLocalizations class which does NOT
  exist yet. The code will not compile until Plan 02 creates app_en.arb and runs
  flutter gen-l10n. This is expected -- Plan 02 depends on Plan 01 and will
  immediately generate the files.

|----------|-------------|
| Build tooling -> runtime | l10n.yaml and ARB files are compile-time assets processed by gen-l10n; no runtime user input crosses this boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Spoofing | Locale resolution | accept | App follows system locale via platformDispatcher.locale; no user-controlled locale override. Fallback to English is safe. |
| T-12-02 | Tampering | ARB files | accept | ARB files are developer-authored compile-time assets, not user-supplied. gen-l10n validates ICU syntax at build time. |
| T-12-SC | Tampering | SDK dependency | accept | flutter_localizations is a Flutter SDK package (ships with Flutter), not a third-party pub.dev package. No slopcheck needed. |
</threat_model>
