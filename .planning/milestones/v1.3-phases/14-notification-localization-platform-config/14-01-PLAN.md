## Goal

Add `notificationBody` to all four ARB files, regenerate AppLocalizations, then update `NotificationService` to resolve the device locale at schedule time and pass localized strings to `_plugin.zonedSchedule()`.

## Context

Before this plan runs:

- `lib/core/services/notification_service.dart` has two hardcoded constants at the top of the class:
  ```
  static const String _notifTitle = 'Drinky Drinky';
  static const String _notifBody = 'Time to drink water!';
  ```
  These are passed verbatim to every `_plugin.zonedSchedule()` call inside `scheduleWindow()`.
- All four ARB files (`app_en.arb`, `app_it.arb`, `app_fr.arb`, `app_es.arb`) end with `"mlUnit": "ml"` as their last key (line 117 of each locale file). None contains a `notificationBody` key.
- `lib/l10n/generated/app_localizations.dart` already exports `lookupAppLocalizations(Locale)` as a top-level function. Its switch covers `en`, `es`, `fr`, `it` by `languageCode`.
- `AppLocalizations.supportedLocales` is `[Locale('en'), Locale('es'), Locale('fr'), Locale('it')]`.
- `main.dart` uses a primary-only locale resolution callback (same algorithm required here, per D-01).

Files touched by this plan:

**3. Add the `_resolveLocale()` helper method** (per D-01). Insert it as a new private method in the class, placed just before the `scheduleWindow()` method (i.e., after the `// Schedule rolling window (D-04)` section comment). The method body is exactly as specified in CONTEXT.md D-01:

```dart
  /// Resolves the device's primary locale to a supported AppLocalizations locale.
  ///
  /// Matches only on [Locale.languageCode] — same strategy as [localeListResolutionCallback]
  /// in main.dart (D-01). Falls back to English for unsupported locales.
  Locale _resolveLocale() {
    final locales = PlatformDispatcher.instance.locales;
    if (locales.isEmpty) return const Locale('en');
    final primary = locales.first;
    for (final supported in AppLocalizations.supportedLocales) {
      if (supported.languageCode == primary.languageCode) return supported;
    }
    return const Locale('en');
  }
```

**4. Update `scheduleWindow()`** to resolve locale and use localized strings.

At the very start of the `scheduleWindow()` method body, after `await cancelAll();` and before `if (!_initialized) return;`, insert:

```dart
    final l10n = lookupAppLocalizations(_resolveLocale());
```

Then, inside the `await _plugin.zonedSchedule(...)` call, replace:

```dart

            body: _notifBody,
```

with:

```dart
            title: l10n.appTitle,
            body: l10n.notificationBody,
```

The final `scheduleWindow()` method should look like this after editing:

```dart
  Future<void> scheduleWindow(UserSettingsEntity settings) async {
    await cancelAll();

    final l10n = lookupAppLocalizations(_resolveLocale());

    if (!_initialized) return;
    if (!(await permissionGranted())) return;

    const int maxSlots = 64;
    int slotId = 1000;
    int scheduled = 0;
    int dayOffset = 0;

    final now = tz.TZDateTime.now(tz.local);

    while (scheduled < maxSlots) {
      if (dayOffset > 30) break;

      var candidate = dayOffset == 0
          ? now.add(Duration(minutes: settings.notificationIntervalMinutes))
          : tz.TZDateTime(
              tz.local,
              now.year,
              now.month,
              now.day + dayOffset,
              0,
              0,
            );

      final dayEnd = tz.TZDateTime(
        tz.local,
        now.year,
        now.month,
        now.day + dayOffset,
        23,
        59,
      );

      while (candidate.isBefore(dayEnd) && scheduled < maxSlots) {
        if (!_isInDnd(candidate, settings)) {
          await _plugin.zonedSchedule(
            id: slotId++,
            scheduledDate: candidate,
            notificationDetails: _notificationDetails,
            androidScheduleMode: AndroidScheduleMode.exactAllowWhileIdle,
            title: l10n.appTitle,
            body: l10n.notificationBody,
            matchDateTimeComponents: null,
          );
          scheduled++;
        }
        candidate = candidate.add(
          Duration(minutes: settings.notificationIntervalMinutes),
        );
      }

      dayOffset++;
    }
  }
```

## Notes

- `lookupAppLocalizations` is a top-level function in `app_localizations.dart`, not a static method — call it as `lookupAppLocalizations(locale)`, not `AppLocalizations.lookup(locale)`.
- `PlatformDispatcher.instance.locales` is available without a `BuildContext` — this is the correct way to read the device locale from a service class.
- The `dart:ui` import uses a `show PlatformDispatcher` clause to avoid polluting the namespace with all of `dart:ui`. This is consistent with `flutter_local_notifications` internals already importing Flutter, so there is no risk of a double-import conflict.
- `_resolveLocale()` must not use `basicLocaleListResolution` (per D-01). The custom primary-only loop is required.
- Task 2 (`flutter gen-l10n`) must execute after all four ARB edits in Task 1 are saved. Running it after only some ARBs are updated will produce an incomplete or inconsistent generated file.
- `l10n.appTitle` returns `"Drinky Drinky"` in all four locales — the notification title is the untranslated app name (per D-02), so reusing `appTitle` is intentional and correct.
