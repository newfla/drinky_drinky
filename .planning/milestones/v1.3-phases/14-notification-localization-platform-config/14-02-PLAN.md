## Goal

Add `CFBundleLocalizations` to `ios/Runner/Info.plist` (L10N-08) and `resourceConfigurations` to `android/app/build.gradle.kts` (L10N-09). These are two independent file edits with no code-generation step.

## Context

Before this plan runs:

- `ios/Runner/Info.plist` has no `CFBundleLocalizations` key. Without it, iOS silently ignores locale changes after the app is installed — the app never signals to the OS which languages it supports, so `PlatformDispatcher.instance.locales` may not reflect the selected device language correctly on first launch or after a locale switch.
- `android/app/build.gradle.kts` uses Kotlin DSL. Its `defaultConfig {}` block (lines 22–31) contains `applicationId`, `minSdk`, `targetSdk`, `versionCode`, and `versionName` but no `resourceConfigurations`. Without this setting, the APK bundles locale resources for every language in every dependency (hundreds of languages from the Android framework), inflating APK size.
- `CFBundleDevelopmentRegion` is already present in `Info.plist` (value: `$(DEVELOPMENT_LANGUAGE)`) — no change needed there (per D-04).

Files touched by this plan:
- `ios/Runner/Info.plist`
- `android/app/build.gradle.kts`

## Tasks

### Task 1: Add CFBundleLocalizations to Info.plist

**File:** `ios/Runner/Info.plist`

**Action:** edit

**Details:**

Insert the `CFBundleLocalizations` key–value pair into the root `<dict>`. The correct insertion point is immediately after the closing `</string>` of the `CFBundleDevelopmentRegion` entry (line 9 in the current file), before `CFBundleDisplayName`. This keeps the plist keys in alphabetical order, which is the convention Apple tooling expects.

The current block around the insertion point is:

```xml
	<key>CFBundleDevelopmentRegion</key>
	<string>$(DEVELOPMENT_LANGUAGE)</string>
	<key>CFBundleDisplayName</key>
	<string>Drinky Drinky</string>
```

Replace with:

```xml
	<key>CFBundleDevelopmentRegion</key>
	<string>$(DEVELOPMENT_LANGUAGE)</string>
	<key>CFBundleLocalizations</key>
	<array>
		<string>en</string>
		<string>it</string>
		<string>fr</string>
		<string>es</string>
	</array>
	<key>CFBundleDisplayName</key>
	<string>Drinky Drinky</string>
```

Indentation uses a single tab character per level, consistent with the rest of the file.

### Task 2: Add resourceConfigurations to build.gradle.kts

**File:** `android/app/build.gradle.kts`

**Action:** edit

**Details:**

Inside the `defaultConfig {}` block, append `resourceConfigurations += setOf("en", "it", "fr", "es")` as the last line before the closing `}` of `defaultConfig`. This is Kotlin DSL syntax — do not use the Groovy form `resConfigs "en", "it", "fr", "es"` (per D-05).

The current `defaultConfig` block is:

```kotlin
    defaultConfig {
        // TODO: Specify your own unique Application ID (https://developer.android.com/studio/build/application-id.html).
        applicationId = "com.bizzarri.drinky_drinky"
        // You can update the following values to match your application needs.
        // For more information, see: https://flutter.dev/to/review-gradle-config.
        minSdk = 26
        targetSdk = flutter.targetSdkVersion
        versionCode = flutter.versionCode
        versionName = flutter.versionName
    }
```

Change to:

```kotlin
    defaultConfig {
        // TODO: Specify your own unique Application ID (https://developer.android.com/studio/build/application-id.html).
        applicationId = "com.bizzarri.drinky_drinky"
        // You can update the following values to match your application needs.
        // For more information, see: https://flutter.dev/to/review-gradle-config.
        minSdk = 26
        targetSdk = flutter.targetSdkVersion
        versionCode = flutter.versionCode
        versionName = flutter.versionName
        resourceConfigurations += setOf("en", "it", "fr", "es")
    }
```

## Verification

1. Validate the plist is well-formed: `plutil -lint ios/Runner/Info.plist` must print `ios/Runner/Info.plist: OK`.
2. Grep check: `grep -c 'CFBundleLocalizations' ios/Runner/Info.plist` must return `1`.
3. Grep check: `grep -A5 'CFBundleLocalizations' ios/Runner/Info.plist` must show `<array>` followed by four `<string>` entries for `en`, `it`, `fr`, `es`.
4. Grep check: `grep -c 'resourceConfigurations' android/app/build.gradle.kts` must return `1`.
5. Grep check: `grep 'resourceConfigurations' android/app/build.gradle.kts` must show `resourceConfigurations += setOf("en", "it", "fr", "es")`.
6. Run `flutter build apk --debug` and confirm the build succeeds with no Gradle errors.

## Notes

- This plan is independent of 14-01 — the two plans touch entirely different files and can be executed in any order or in parallel.
- The `CFBundleLocalizations` array does not need to include `en` separately from `$(DEVELOPMENT_LANGUAGE)` — but including `en` explicitly is harmless and makes the supported set unambiguous. All four locales (en, it, fr, es) must appear.
- On iOS, without `CFBundleLocalizations`, the OS may not pass the correct preferred locale to the Flutter engine even if `supportedLocales` in `MaterialApp.router` is correctly configured. This entry is the iOS-side handshake that declares "this app knows about these languages."
- The `resourceConfigurations` line must be inside `defaultConfig {}`, not inside `buildTypes {}` or at the `android {}` level. The Kotlin DSL property is `resourceConfigurations` (not `resConfig` or `resConfigs`). The `+=` operator appends to the existing set rather than replacing it, which is the idiomatic Kotlin DSL form.
- `plutil` is available on macOS (Xcode CLI tools). If running on Linux CI, substitute with `xmllint --noout ios/Runner/Info.plist` for well-formedness checking.
