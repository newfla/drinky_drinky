## Phase Goal

Notification reminders arrive in the user's language and both iOS and Android correctly detect the app's supported locales.

## Decisions

### D-01: Notification locale resolution strategy [LOCKED]

`NotificationService.scheduleWindow()` resolves the locale using the same strategy as `main.dart` — primary locale only, English fallback for unsupported languages. Do NOT use `basicLocaleListResolution` (which iterates the full preferred-language list).

**Implementation:**
```dart
Locale _resolveLocale() {
  final locales = PlatformDispatcher.instance.locales;
  if (locales.isEmpty) return const Locale('en');
  final primary = locales.first;
  for (final supported in AppLocalizations.supportedLocales) {
    if (supported.languageCode == primary.languageCode) return supported;
  }
  return const Locale('en');
}
```

Then: `final l10n = lookupAppLocalizations(_resolveLocale());`

**Why:** Matches the UAT T7 decision. Prevents Spanish notifications when German is the primary locale. Consistent with `localeListResolutionCallback` in `main.dart`.

### D-02: Notification title [LOCKED]

The notification title stays as the untranslated app name **"Drinky Drinky"**. Reuse the existing `appTitle` ARB key (already "Drinky Drinky" in all 4 ARBs). No new ARB key needed for the title.

The notification body carries all localized content.

### D-03: Notification body ARB key [LOCKED]

Add a single new key `notificationBody` to `app_en.arb` (and all locale ARBs) for the reminder body text. English value: `"Time to drink water! 💧"`. No other new keys required.

Translations:
- `it`: `"È ora di bere acqua! 💧"`
- `fr`: `"C'est l'heure de boire de l'eau ! 💧"`
- `es`: `"¡Es hora de beber agua! 💧"`

### D-04: iOS platform config [LOCKED]

Add `CFBundleLocalizations` to `ios/Runner/Info.plist` with values `en`, `it`, `fr`, `es`. Required or iOS silently ignores locale changes.

No `CFBundleDevelopmentRegion` change needed — it already inherits from `$(DEVELOPMENT_LANGUAGE)`.

### D-05: Android platform config [LOCKED]

Add `resourceConfigurations += setOf("en", "it", "fr", "es")` inside `defaultConfig` in `android/app/build.gradle.kts`. Strips unneeded locale resource files from the APK.

## Technical Notes

- `lookupAppLocalizations` is available from `lib/l10n/generated/app_localizations.dart` (generated by `flutter gen-l10n`).
- `PlatformDispatcher.instance` is accessible from `notification_service.dart` via `dart:ui` — no extra import needed since `flutter_local_notifications` already imports Flutter.
- Import needed: `import 'dart:ui' show PlatformDispatcher;` and `import '../../l10n/generated/app_localizations.dart';`.
- After adding `notificationBody` to ARBs, re-run `flutter gen-l10n` to regenerate the `AppLocalizations` class.
- The emoji 💧 is included in all notification body translations — lightweight brand touch.
- `resourceConfigurations` in Kotlin DSL is `resourceConfigurations += setOf(...)` inside `defaultConfig { }`.
