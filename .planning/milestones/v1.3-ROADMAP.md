# Milestone v1.3: Multilingual Support

**Status:** ✅ SHIPPED 2026-06-15
**Phases:** 12-14
**Total Plans:** 6

## Overview

App follows system language — Italian, English, French, and Spanish; English as fallback for unsupported locales. Full gen-l10n pipeline, 79-key ARB template with complete translations, enum refactor for locale-safe computation, localized notifications via PlatformDispatcher, and platform locale declarations on both iOS and Android.

## Phases

### Phase 12: L10n Infrastructure

**Goal**: App has a working localization pipeline that resolves the device locale and provides translated Material widgets
**Depends on**: Phase 11 (v1.2 complete)
**Requirements**: L10N-01, L10N-02, L10N-03
**Plans**: 2 plans

Plans:

- [x] 12-01-PLAN.md — L10n pipeline setup (pubspec, l10n.yaml, MaterialApp wiring, initializeDateFormatting, TableCalendar locale, context extension)
- [x] 12-02-PLAN.md — Complete app_en.arb (79 English strings) + flutter gen-l10n generation

**Success Criteria:**

  1. `flutter gen-l10n` runs without errors and generates `AppLocalizations` class with `of(context)` accessor
  2. App launched on a device set to Italian/French/Spanish shows localized Material widget text (date picker buttons, dialog actions)
  3. App launched on an unsupported locale (e.g., German) falls back to English strings
  4. `table_calendar` displays month and day names in the device's language

**Key decisions:**
- `synthetic-package: false`, `output-dir: lib/l10n/generated/`, `nullable-getter: false` — required on Flutter 3.44.1 to avoid analyzer conflicts with the existing package namespace
- `context.l10n` ergonomic extension via `AppLocalizationsX` on `BuildContext` — single-import accessor for all 6 screens
- `initializeDateFormatting()` called before `runApp()` — required for `table_calendar` day/month name localization via intl

### Phase 13: String Extraction & Translation

**Goal**: Every user-visible string in the app displays in the device's language (it/en/fr/es)
**Depends on**: Phase 12
**Requirements**: L10N-04, L10N-05, L10N-06
**Plans**: 2 plans

Plans:

- [x] 13-01-PLAN.md — BiologicalSex/ClimateLevel enum refactor + widget string replacement with context.l10n across all screens
- [x] 13-02-PLAN.md — Complete app_it.arb, app_fr.arb, app_es.arb (79 keys each) + flutter gen-l10n regeneration

**Success Criteria:**

  1. Calculator screen displays sex/climate labels in the device's language without crashing (enum-based computation, not string-keyed)
  2. All 6 screens (home, settings, history/calendar, calculator, permission screen, add-intake sheet) show fully translated text with no hardcoded Italian or English remnants
  3. Plural forms render correctly in all 4 languages (e.g., French "0 jour" singular, streak counters)
  4. `app_en.arb` serves as the canonical template with semantic keys and `@key` metadata for all extractable strings

**Key decisions:**
- `BiologicalSex` and `ClimateLevel` enums replace Italian display-string map keys — prerequisite for crash-free locale switching
- ICU plural syntax with explicit `=0`/`=1`/`other` cases — French uses `one` category for 0 and 1 (different from English)
- Primary-locale-only resolution via `localeListResolutionCallback` — matches `locales.first`, English fallback for unsupported
- 3 inline UAT fixes: ring text centering, Italian todaysIntake string, Spanish todaysIntake preference ("Historial de hoy")

### Phase 14: Notification Localization & Platform Config

**Goal**: Notification reminders arrive in the user's language and both iOS and Android correctly detect the app's supported locales
**Depends on**: Phase 12
**Requirements**: L10N-07, L10N-08, L10N-09
**Plans**: 2 plans

Plans:

- [x] 14-01-PLAN.md — notificationBody ARB key (4 locales) + NotificationService locale resolver + lookupAppLocalizations
- [x] 14-02-PLAN.md — CFBundleLocalizations to iOS Info.plist + resourceConfigurations to Android build.gradle.kts

**Success Criteria:**

  1. Hydration reminder notification title and body text appear in the device's language (it/en/fr/es)
  2. On iOS, switching device language to Italian/French/Spanish causes the app to follow the new locale (CFBundleLocalizations declared)
  3. Android APK bundles only en/it/fr/es locale resources (resConfigs filtering active)

**Key decisions:**
- `PlatformDispatcher.instance.locales` + `lookupAppLocalizations()` for service-layer locale resolution without BuildContext
- Primary-only matching consistent with Phase 13's `localeListResolutionCallback` in main.dart
- `CFBundleLocalizations` includes `en` explicitly alongside it/fr/es — harmless and makes the set unambiguous
- `resourceConfigurations += setOf(...)` Kotlin DSL syntax in build.gradle.kts
- Code review fixes: guard ordering (initialized → permissionGranted → intervalMinutes > 0 → cancelAll), zero-interval infinite loop protection, try/catch English fallback on lookupAppLocalizations

## Milestone Summary

**Key Decisions:**

- `synthetic-package: false` for gen-l10n on Flutter 3.44.1 (analyzer namespace conflict workaround)
- Enum-based locale-safe computation for BiologicalSex/ClimateLevel (replaced Italian string keys)
- Primary-only locale resolution strategy (locales.first, English fallback) — consistent between UI and notifications
- PlatformDispatcher + lookupAppLocalizations for service-layer locale access (no BuildContext needed)
- CFBundleLocalizations required on iOS for OS → Flutter locale propagation to work reliably

**Issues Resolved:**

- Calculator screen crash on non-Italian locales (Italian string key lookup in a locale-sensitive map)
- NotificationService zero-interval infinite loop (missing guard before scheduling loop)
- NotificationService guard ordering bug (cancelAll ran before permissionGranted check)
- 3 UAT-driven string corrections (ring text, Italian/Spanish todaysIntake)

**Issues Deferred:**

- Native human review of Italian/French/Spanish translations — machine-generated in v1.3; quality gate deferred to v1.4+
- German (de) and Portuguese (pt) locale support — out of scope for v1.3
- Notification channel name localization — rarely visible; deferred to v1.4+

**Technical Debt Incurred:**

- ARB translations are machine-generated; native speaker review recommended before wide distribution
- `minSdk = 26` in build.gradle.kts (pre-existing from Phase 1 scaffold; CLAUDE.md documents minSdk 24 — cosmetic inconsistency, no functional impact)
